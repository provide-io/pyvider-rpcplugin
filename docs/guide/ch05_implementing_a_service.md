# Chapter 5: Implementing a Service (Echo Demo)

Now, let's build a plugin server that provides an actual RPC service. We'll use a simple "Echo" service as an example. This involves defining the service interface, implementing the server-side logic, and integrating it with `pyvider.rpcplugin`.

## 1. Defining the Service with Protocol Buffers (`.proto`)

gRPC services are typically defined using Protocol Buffers (Protobufs). You create a `.proto` file to specify your service methods and the structure of the request and reply messages.

**Example `echo.proto`:**
```protobuf
syntax = "proto3";

package echo; // Defines the package, useful for preventing name collisions.

// The Echo service definition.
service EchoService {
  // Sends a message and receives the same message back.
  rpc Echo (EchoRequest) returns (EchoResponse) {}
}

// The request message containing the message to be echoed.
message EchoRequest {
  string message = 1;
}

// The response message containing the echoed message.
message EchoResponse {
  string reply = 1;
}
```
**Compilation:**
You would then use the gRPC tools for Python (`grpcio-tools`) to compile this `.proto` file. This generates two Python files:
*   `echo_pb2.py`: Contains the Python classes for your message types (`EchoRequest`, `EchoResponse`).
*   `echo_pb2_grpc.py`: Contains:
    *   Client stub classes (`EchoServiceStub`) for making calls to the service.
    *   Server servicer base classes (`EchoServiceServicer`) that you inherit from to implement the service.
    *   A function to register your servicer with a gRPC server (`add_EchoServiceServicer_to_server`).

The `examples/proto/` directory in the `pyvider.rpcplugin` repository contains `echo.proto` and its pre-generated Python files (`echo_pb2.py`, `echo_pb2_grpc.py`).

Command to compile (run from the directory containing `echo.proto`, e.g., `examples/proto/`):
```bash
# Assuming you are in examples/proto/
python -m grpc_tools.protoc -I. --python_out=. --grpc_python_out=. --pyi_out=. echo.proto
# Or from project root:
# python -m grpc_tools.protoc -I./examples/proto --python_out=./examples/proto --grpc_python_out=./examples/proto --pyi_out=./examples/proto ./examples/proto/echo.proto
```

## 2. Implementing the gRPC Servicer (Handler)

The "Handler" is your Python class that implements the actual logic for the RPC methods defined in your service. This class must inherit from the `YourServiceServicer` base class generated by `grpcio-tools` (e.g., `EchoServiceServicer` from `echo_pb2_grpc.py`).

Each method in your handler must be an `async def` method corresponding to an `rpc` method in your `.proto` definition. It will take two arguments: the request message object and a context object (typically `grpc.aio.ServicerContext`).

## 3. Implementing the `RPCPluginProtocol`

To integrate your gRPC service with `RPCPluginServer`, you create a class that inherits from `pyvider.rpcplugin.protocol.base.RPCPluginProtocol`. This class acts as a bridge.

Key methods to implement:
*   `async get_grpc_descriptors(self) -> tuple[Any, str]`: This method should return a tuple containing:
    1.  The generated `_pb2_grpc.py` module (which includes service descriptors).
    2.  A string representing the fully qualified service name (e.g., `"echo.EchoService"`).
*   `async add_to_server(self, server: Any, handler: Any) -> None`: This method is responsible for registering your handler (servicer) with the gRPC server instance managed by `RPCPluginServer`. You'll use the `add_YourServiceServicer_to_server` function generated by `grpcio-tools`.
*   `get_method_type(self, method_name: str) -> str`: (Optional for basic unary RPCs, but good practice to implement). This method should return a string indicating the type of RPC method (e.g., `"unary_unary"`, `"unary_stream"`, `"stream_unary"`, `"stream_stream"`). This can be important for some middleware or advanced routing, though for simple cases, a default might suffice.

## Example: Echo Server Implementation (`examples/05_echo_server.py`)

The following example shows a runnable Echo plugin server, `examples/05_echo_server.py`, which uses the `examples/proto/echo.proto` definitions. This server is designed to be launched by `examples/07_echo_client.py`.

```python
#!/usr/bin/env python3
# examples/05_echo_server.py
import asyncio
import os
from typing import Any, cast
import grpc

# Import generated code from the examples/proto directory
# Assumes 'examples' is in PYTHONPATH or you run from project root.
from examples.proto import echo_pb2, echo_pb2_grpc

# Import pyvider components
from pyvider.rpcplugin.factories import plugin_server
from pyvider.rpcplugin.protocol.base import RPCPluginProtocol
from pyvider.rpcplugin.server import RPCPluginServer
from pyvider.rpcplugin.types import RPCPluginProtocol as TypesRPCPluginProtocol
from pyvider.telemetry import logger

# --- Implement the Handler (Servicer) ---
class EchoHandler(echo_pb2_grpc.EchoServiceServicer):
    async def Echo(
        self, request: echo_pb2.EchoRequest, context: grpc.aio.ServicerContext
    ) -> echo_pb2.EchoResponse:
        logger.info(f"Handler: Received Echo request: '{request.message}'")
        reply_message = f"Server echoed: {request.message}"
        return echo_pb2.EchoResponse(reply=reply_message)

# --- Implement the Protocol Wrapper ---
class EchoProtocol(RPCPluginProtocol):
    async def get_grpc_descriptors(self) -> tuple[Any, str]:
        # Return the generated _pb2_grpc module and the Service name string
        return echo_pb2_grpc, "echo.EchoService" # Matches package.Service from .proto

    def get_method_type(self, method_name: str) -> str:
        # For this EchoService, 'Echo' is unary-unary.
        if "Echo" in method_name: # A more robust check might inspect descriptors
            return "unary_unary"
        logger.warning(f"Unknown method {method_name} in EchoProtocol, defaulting to unary_unary.")
        return "unary_unary" # Default for safety

    async def add_to_server(self, server: Any, handler: Any) -> None:
        # Register the handler with the gRPC server
        echo_pb2_grpc.add_EchoServiceServicer_to_server(
            cast(EchoHandler, handler), server
        )
        logger.info("EchoService handler registered with gRPC server.")

# --- Main Server Logic ---
async def main() -> None:
    logger.info("Starting Echo Plugin Server (05_echo_server.py)...")

    # Basic env setup for standalone run, mimicking what a client might set.
    # In a real plugin scenario, these are set by the host application.
    # example_utils.configure_for_example() might handle this if called early.
    if "PLUGIN_MAGIC_COOKIE_KEY" not in os.environ:
        # This check is for the key, the value is set by the client.
        # The server reads the value from the key specified by PLUGIN_MAGIC_COOKIE_KEY.
        logger.warning(
            "PLUGIN_MAGIC_COOKIE_KEY env var not set. Using default for standalone run."
        )
        os.environ["PLUGIN_MAGIC_COOKIE_KEY"] = "ECHO_PLUGIN_COOKIE_EXAMPLE"
        # The actual cookie value is usually set by the client that launches this server.
        # For standalone testing, if the client isn't setting it,
        # the server might need a default value for PLUGIN_MAGIC_COOKIE_VALUE
        # if it's directly checking it, rather than just the handshake output.
        # However, standard behavior is server prints handshake, client verifies it.
        # The server itself doesn't need PLUGIN_MAGIC_COOKIE or PLUGIN_MAGIC_COOKIE_VALUE
        # to *start*, but it needs to output them correctly during handshake if hardcoded.
        # The `plugin_server` factory and `RPCPluginServer` handle handshake output
        # based on env vars like `PLUGIN_HOST_ADDRESS`, `PLUGIN_MAGIC_COOKIE_VALUE` (if set for it to use).
        # For this example, we'll rely on the client to set the value.

    handler = EchoHandler()
    # Ensure EchoProtocol is cast to the expected base type for plugin_server
    echo_protocol_instance = cast(TypesRPCPluginProtocol, EchoProtocol())

    server: RPCPluginServer = plugin_server(
        protocol=echo_protocol_instance,
        handler=handler,
        # transport='unix' # Default, or 'tcp' can be specified
    )

    try:
        # This runs the server, including the handshake, and starts serving.
        await server.serve()
    except Exception as e:
        logger.error(f"Server execution failed: {e}", exc_info=True)
    finally:
        logger.info("Echo server (05_echo_server.py) shutting down.")
        # server.stop() is called within RPCPluginServer.serve()'s finally block.

if __name__ == "__main__":
    try:
        from examples.example_utils import configure_for_example
        configure_for_example() # For path setup, global config defaults
        asyncio.run(main())
    except KeyboardInterrupt: # pragma: no cover
        logger.info("Server stopped by user.")
```

**Key elements in the `05_echo_server.py` example:**

*   **`EchoHandler(echo_pb2_grpc.EchoServiceServicer)`**:
    *   This class inherits from the generated `EchoServiceServicer`.
    *   It implements the `async def Echo(...)` method, which contains the logic for handling the `Echo` RPC call.
*   **`EchoProtocol(RPCPluginProtocol)`**:
    *   `get_grpc_descriptors()`: Returns `echo_pb2_grpc` (the module containing service registration functions and stubs) and the string `"echo.EchoService"` (which is `package.ServiceName` from the `.proto` file).
    *   `add_to_server()`: This method is crucial. It calls the generated `echo_pb2_grpc.add_EchoServiceServicer_to_server(handler, server)`. This function is what actually registers your `EchoHandler` with the underlying gRPC server instance that `RPCPluginServer` manages.
    *   `get_method_type()`: Provides information about the RPC method types.
*   **`main()` function**:
    *   Instantiates `EchoHandler` and `EchoProtocol`.
    *   Uses the `plugin_server` factory to create an `RPCPluginServer` instance, passing in the protocol and handler.
    *   Calls `await server.serve()` to start the handshake process and begin serving RPC requests.
    *   Includes basic environment variable setup for the magic cookie to allow the server to be run standalone for testing (normally, the client launching the plugin would set these).

This server, using `examples/proto/echo.proto`, can be compiled into an executable or run directly. When launched by an `RPCPluginClient`, it will perform the handshake and then be ready to serve `Echo` requests.
