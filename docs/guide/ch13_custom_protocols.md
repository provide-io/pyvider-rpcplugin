# Chapter 13: Custom Protocols & Middleware

While `pyvider.rpcplugin` aims to simplify plugin development by handling common gRPC setup and handshake logic, there might be scenarios where you need more control over the protocol definition or wish to introduce middleware-like behavior.

## Custom `RPCPluginProtocol`

You can create a custom protocol by inheriting from `pyvider.rpcplugin.protocol.base.RPCPluginProtocol`. This is necessary when:

1.  **You have defined your own gRPC services in `.proto` files**: The primary use case. Your custom protocol implementation will tell `RPCPluginServer` how to register and serve these custom gRPC services.
2.  **Managing Multiple gRPC Services**: A single plugin executable might expose multiple distinct gRPC services. A custom `RPCPluginProtocol` can manage the registration of all these services.
3.  **Altering Service Registration**: You need fine-grained control over how services are added to the `grpc.aio.Server` instance.

**Key methods to implement in your custom protocol:**

*   `async def get_grpc_descriptors(self) -> tuple[Any, str]`:
    *   **Returns**: A tuple where the first element is the Python module generated by `grpc_tools` from your `.proto` file (this module contains service descriptors and registration functions like `add_YourServiceServicer_to_server`). The second element is the fully qualified name of your primary service (e.g., `"mypackage.MyService"`).
    *   If you have multiple services, you might return the descriptors for the "main" one or handle them all within `add_to_server`.
*   `async def add_to_server(self, server: Any, handler: Any) -> None`:
    *   `server`: The `grpc.aio.Server` instance managed by `RPCPluginServer`.
    *   `handler`: The instance of your servicer class (which implements the RPC methods).
    *   **Action**: Call the appropriate `add_YourServiceServicer_to_server(handler, server)` function (generated by `grpc_tools`) for each gRPC service your plugin provides.
*   `def get_method_type(self, method_name: str) -> str`:
    *   **Returns**: A string indicating the gRPC method type (e.g., `"unary_unary"`, `"unary_stream"`, `"stream_unary"`, `"stream_stream"`). This is used by some internal components or could be used by custom interceptors/middleware. You should map your RPC method names to their types.

Refer to **Chapter 5: Implementing a Service (Echo Demo)** for a concrete example (`EchoProtocol`) of a custom protocol implementation.

## Middleware-like Patterns

While `pyvider.rpcplugin` itself doesn't have a dedicated middleware framework separate from gRPC, you can achieve middleware-like behavior for cross-cutting concerns (logging, metrics, custom authentication/authorization per call) primarily through:

1.  **gRPC Interceptors**: This is the standard and recommended way to intercept RPC calls on both the client and server side in gRPC.
    *   **Server Interceptors**: Implemented as classes inheriting from `grpc.aio.ServerInterceptor`. They can inspect and modify requests and responses, or execute logic before or after an RPC method is called. `RPCPluginServer` allows you to pass a list of interceptors when it creates the `grpc.aio.Server`.
    *   **Client Interceptors**: Implemented similarly (e.g., `grpc.aio.ClientInterceptor`) and can be applied when creating a gRPC channel or stub.
2.  **Decorators or Wrappers**: You can wrap your handler methods with decorators or create wrapper classes around your handler instance to inject behavior. The `examples/09_custom_protocols.py` demonstrates a conceptual version of this.

### Example: Custom Protocols and Conceptual Middleware (`examples/09_custom_protocols.py`)

This example shows how a custom protocol might be structured and how one could conceptually apply middleware by wrapping handler methods. **Note**: For actual RPC interception, gRPC Interceptors are preferred over the manual `__getattr__` wrapping shown in this example for middleware.

```python
#!/usr/bin/env python3
# examples/09_custom_protocols.py
import asyncio
from typing import Any
from example_utils import configure_for_example
configure_for_example() # Basic example setup

from pyvider.rpcplugin.protocol.base import RPCPluginProtocol
from pyvider.telemetry import logger

class CustomProtocol(RPCPluginProtocol):
    """Example custom protocol, demonstrating structure and conceptual middleware."""
    def __init__(self, service_name: str = "CustomService"):
        super().__init__()
        self.service_name = service_name
        self.middleware_factories: list[Any] = [] # Stores middleware factories

    async def get_grpc_descriptors(self):
        logger.info(f"🔌 Descriptors requested for {self.service_name}")
        # For a real gRPC service, return compiled_pb2_grpc, "package.ServiceName"
        return None, self.service_name # No actual gRPC service in this demo

    def get_method_type(self, method_name: str) -> str:
        # Example: map method names to their gRPC types
        method_types = {
            "ProcessData": "unary_unary",
            "StreamData": "unary_stream",
        }
        return method_types.get(method_name, "unary_unary") # Default

    async def add_to_server(self, server: Any, handler: Any) -> None:
        """
        In a real scenario, 'server' is grpc.aio.Server.
        'handler' is your gRPC servicer instance.
        This method would call generated add_Servicer_to_server functions.
        """
        logger.info(f"🔧 Registering {self.service_name} to gRPC server.")

        # Conceptually apply middleware to the handler before registration
        wrapped_handler = self._apply_middleware(handler)

        # Placeholder for actual gRPC registration:
        # your_service_pb2_grpc.add_YourServiceServicer_to_server(wrapped_handler, server)
        logger.info(
            f"✅ {self.service_name} (with {len(self.middleware_factories)} middleware layers) "
            "would be registered with the gRPC server here."
        )

    def add_middleware(self, middleware_factory: Any):
        """Adds a middleware factory to the stack."""
        self.middleware_factories.append(middleware_factory)
        logger.info(f"➕ Added middleware factory: {middleware_factory.__name__ if hasattr(middleware_factory, '__name__') else middleware_factory}")

    def _apply_middleware(self, handler: Any) -> Any:
        """Applies the middleware stack to a handler instance."""
        wrapped_handler = handler
        for factory in reversed(self.middleware_factories):
            # Each factory takes the current handler and returns a new wrapped one
            wrapped_handler = factory(wrapped_handler)
        return wrapped_handler

# Conceptual Middleware Examples (Illustrative of wrapping, not direct gRPC interceptors)
class LoggingMiddleware:
    def __init__(self, next_handler: Any):
        self.next_handler = next_handler
        logger.info("LoggingMiddleware initialized.")

    async def __getattr__(self, name: str) -> Any:
        original_method = getattr(self.next_handler, name)
        if callable(original_method) and asyncio.iscoroutinefunction(original_method):
            async def logged_method(*args: Any, **kwargs: Any) -> Any:
                logger.info(f"📝 [LOG] Calling: {self.next_handler.__class__.__name__}.{name}")
                try:
                    result = await original_method(*args, **kwargs)
                    logger.info(f"✅ [LOG] Completed: {name}")
                    return result
                except Exception as e:
                    logger.error(f"❌ [LOG] Error in {name}: {e}")
                    raise
            return logged_method
        return original_method

class TimingMiddleware:
    def __init__(self, next_handler: Any):
        self.next_handler = next_handler
        logger.info("TimingMiddleware initialized.")

    async def __getattr__(self, name: str) -> Any:
        original_method = getattr(self.next_handler, name)
        if callable(original_method) and asyncio.iscoroutinefunction(original_method):
            async def timed_method(*args: Any, **kwargs: Any) -> Any:
                start_time = time.perf_counter()
                try:
                    result = await original_method(*args, **kwargs)
                    duration = time.perf_counter() - start_time
                    logger.info(f"⏱️  [TIMING] {name} took {duration:.4f}s")
                    return result
                except Exception as e:
                    duration = time.perf_counter() - start_time
                    logger.error(f"⏱️  [TIMING] {name} failed after {duration:.4f}s: {e}")
                    raise
            return timed_method
        return original_method

class DummyServiceHandler:
    async def ProcessData(self, request: Any, context: Any) -> str:
        logger.info("  Handler: ProcessData called")
        await asyncio.sleep(0.05) # Simulate work
        return f"Processed: {request}"

async def custom_protocol_demo():
    logger.info("🔧 Custom Protocol with Middleware Demo")

    protocol = CustomProtocol("MyDataService")
    protocol.add_middleware(LoggingMiddleware) # LoggingMiddleware factory
    protocol.add_middleware(TimingMiddleware)  # TimingMiddleware factory

    original_handler = DummyServiceHandler()

    # Simulate what add_to_server would do with the wrapped handler
    # This doesn't involve actual gRPC server for this specific example part.
    wrapped_handler_for_simulation = protocol._apply_middleware(original_handler)

    logger.info("Simulating call to wrapped ProcessData...")
    if hasattr(wrapped_handler_for_simulation, "ProcessData"):
        await wrapped_handler_for_simulation.ProcessData("SampleRequest", None)

    logger.info("✅ Custom protocol with middleware demo completed.")

async def main():
    await custom_protocol_demo()

if __name__ == "__main__":
    asyncio.run(main())
```

**Key points from this conceptual example:**

*   `CustomProtocol` demonstrates the structure of a protocol implementation.
*   The `LoggingMiddleware` and `TimingMiddleware` are illustrative examples of how one *might* wrap handler methods to add cross-cutting concerns.
*   **Important**: For real-world gRPC applications, using official **gRPC Interceptors** is the more standard and robust way to achieve middleware functionality for RPC calls. You can provide these interceptors when `RPCPluginServer` creates the `grpc.aio.Server`. The `_apply_middleware` pattern shown in the example is more for conceptual understanding of wrapping or for non-gRPC specific AOP (Aspect-Oriented Programming) patterns.
