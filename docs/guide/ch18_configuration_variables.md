# Chapter 18: Configuration Variables

`pyvider.rpcplugin` is configured primarily through environment variables or programmatically via the `RPCPluginConfig` singleton (accessed as `rpcplugin_config`) or the `configure()` helper function. All environment variables recognized by the library are prefixed with `PLUGIN_`.

When using environment variables, the library will automatically attempt to convert their string values to the appropriate Python types (e.g., boolean, integer, float, list of strings, list of integers) based on the schema.

Below is a comprehensive list of configuration variables, their purpose, expected type, and default values. This information is derived from the `CONFIG_SCHEMA` within `src/pyvider/rpcplugin/config.py`.

| Environment Variable Name                 | Programmatic Key (`rpcplugin_config.get`) | Type       | Default Value(s)                      | Description                                                                                                                               |
| ----------------------------------------- | ----------------------------------------- | ---------- | ------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
|                                           | `SUPPORTED_PROTOCOL_VERSIONS`             | `list_int` | `[1, 2, 3, 4, 5, 6, 7]`               | Internal list of Plugin Protocol Versions the `rpcplugin` library itself supports. Not typically user-configured.                           |
| `PLUGIN_CORE_VERSION`                     | `PLUGIN_CORE_VERSION`                     | `int`      | `1`                                   | The core RPC Plugin handshake version. This rarely changes and must match between client and server for the initial handshake line parsing. |
| `PLUGIN_LOG_LEVEL`                        | `PLUGIN_LOG_LEVEL`                        | `str`      | `INFO`                                | Logging level for `pyvider.telemetry`. Valid values: `DEBUG`, `INFO`, `WARNING`, `ERROR`, `CRITICAL`.                                      |
| `PLUGIN_MAGIC_COOKIE_KEY`                 | `PLUGIN_MAGIC_COOKIE_KEY`                 | `str`      | `PLUGIN_MAGIC_COOKIE`                 | The name of the environment variable that the client will set in the plugin's environment. The server will read this environment variable to obtain the actual magic cookie string provided by the client. |
| `PLUGIN_MAGIC_COOKIE_VALUE`               | `PLUGIN_MAGIC_COOKIE_VALUE`               | `str`      | `test_cookie_value`                   | The actual secret string that the client will send and the server expects for authentication. | `PLUGIN_CLIENT_RETRY_JITTER_MS`           | `PLUGIN_CLIENT_RETRY_JITTER_MS`           | `int`      | `100`                                 | Maximum random jitter in milliseconds to add to backoff delays, helping to prevent thundering herd scenarios.                          |

| `PLUGIN_HEALTH_SERVICE_ENABLED`           | `PLUGIN_HEALTH_SERVICE_ENABLED`           | `bool`     | `true`                                | If "true", the `RPCPluginServer` will register and serve the standard gRPC health checking service.                                    |

**Boolean Value Conversion:**
For boolean settings, values like `"true"`, `"yes"`, `"1"`, `"on"` (case-insensitive) are interpreted as `True`. All other string values are interpreted as `False`.

**List Value Conversion:**
For list settings (e.g., `PLUGIN_PROTOCOL_VERSIONS`, `PLUGIN_SERVER_TRANSPORTS`), provide a comma-separated string of values (e.g., `"unix,tcp"` or `"1,2,5"`). Spaces around commas are automatically stripped.

**File Paths:**
For configuration values that expect file paths (like certificates and keys), you can either provide the direct PEM content as a string or use a `file:///` URI to point to a file on the filesystem (e.g., `PLUGIN_SERVER_CERT="file:///etc/certs/server.pem"`).
